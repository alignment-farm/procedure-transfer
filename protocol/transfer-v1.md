# Transfer v1 — frozen after development, before prospective training/evaluation

Question: on a fully condition-covered synthetic routing task, does a fixed evidence-conditioned teacher improve context-free new-identifier performance beyond direct imitation of the same 16 checked calls? Secondary contrast holds reverse KL fixed and varies checked versus current-student response prefixes.

Evidence is four invented identifiers (lengths 3–6) crossed with both channels and priorities, 16 deterministic oracle answers. Teacher receives all checked calls, including the answer for the current training input, plus the generic induction reminder recorded verbatim in scripts/task.py. The reminder requests a consistent protocol accounting for both fields and argument changes; it supplies no tool mapping, casing or suffix answer. It is a researcher-authored inductive cue, available only on the teacher/reference path. Student training prompts contain only the schema and input. No extra unique training inputs, rule text, synthetic answers, verifier feedback, reflection, or online memory updates. Teacher contributes pretrained knowledge and full next-token distributions, including on incorrect student prefixes. All arms use the same Qwen3-4B-Instruct-2507 revision and vocabulary. This is a supervised fixed-evidence adaptation, not autonomous acquisition or a reproduction of OPCD/PMD.

Assumptions: routing and string transformation are stationary across identifiers; uppercase and optional suffix compose independently. All four condition combinations are observed. Finite examples do not uniquely identify every possible program. Evaluation therefore tests new-identifier transfer under these assumptions, not inference of an unseen condition combination or arbitrary new procedures.

Three independently reset treatments for seeds 17 and 29: (1) answer/EOS cross-entropy imitation; (2) full-vocabulary reverse KL on the checked answer/EOS prefixes; (3) same reverse KL on fresh student-sampled prefixes. For each seed, identical initial LoRA values and shuffled training-input order across methods. Teacher is frozen base (zero adapter), never updated. Distillation loss is mean over response positions of sum_v p_student(v)*(log p_student(v)-log p_teacher(v)); teacher and sampled discrete prefixes are stop-gradient, no score-function term. Float32 log-softmax and loss. Full vocabulary is a deliberate adaptation of the paper's top-256 approximation. On-policy samples at temperature 1, no top-p/top-k restriction, one rollout per update, maximum 48 tokens including EOS. Natural EOS is included in loss; truncated responses get no invented EOS. Checked responses always include EOS.

Training recipe: last eight blocks, query and value LoRA, rank 8, scale 2, dropout 0; AdamW 0.0005, weight decay 0; batch size one; eight epochs over all 16 inputs = 128 updates per treatment/seed. Same optimizer steps are not equal compute or supervised-token budgets. Select the final checkpoint unconditionally, no checkpoint search, no evaluation during training. The native pilot verifies mechanics only, not selection of this recipe by student transfer scores. A second development pilot selects one generic teacher reminder versus the original prompt using the same 16 development labels; no learner-transfer scores are used. Six runs total; no parameter sweep or later-learning extension. Native peak allocation ceiling 40 GB, main run limit 90 minutes. Preserve failure records; implementation repairs allowed but no outcome-driven recipe changes.

Development: 16 tasks crossing four different invented identifiers with all conditions. Greedy base/no-evidence, all-examples and supplied-rule references diagnose teacher usefulness. Development is not final evidence. The first prompt scored 9/16 with examples versus 0/16 without evidence and 16/16 with a supplied rule. One generic induction reminder scored 16/16; the predeclared rule was to adopt it only if it exceeded 9/16, with no further variants. The reminder is therefore selected. Freeze this file and implementation in Git after feasibility, before running the comparison.

Prospective evaluation: construct only after all six checkpoints are fixed, using Python Random(2026091401), six unique lowercase ASCII identifiers per length 4,6,8,10 (exclude training and development), crossed with four conditions = 96 calls per branch. This seed is committed before construction. Evaluate no-update base, base with the 16 examples, privileged complete rule, and all six final adapters without evidence. Also evaluate 16 training cases separately for each adapter and the evidence-conditioned base. All greedy, maximum 48 tokens, exact call match after outer whitespace stripping; no retries, semantic repair or constrained decoding. Preserve prompt and output token IDs and raw text. No repeated evaluation passes counted as additional evidence.

Primary outcome: mean accuracy across the two training seeds and per-seed paired differences, on-policy minus imitation. Secondary: on-policy minus checked-prefix reverse KL. Report paired differences and a descriptive 95% bootstrap interval resampling the 24 identifiers as clusters, retaining all four conditions and both seeds (10,000 resamples, seed 20260914). A positive local advantage requires positive differences in both seeds and a positive lower interval endpoint; otherwise report no established advantage for this recipe. These intervals condition on two chosen seeds and one task, not population evidence across models or procedures. Report each length stratum and training recall. A secondary trajectory claim is local to fixed reverse KL; comparison to imitation combines loss and teacher supervision differences.

Costs: record setup/download separately; acquisition is 16 researcher-oracle labels, no environment exploration. Development uses 16 additional oracle labels for teacher feasibility (not learner supervision); evaluation uses 96 held-out oracle labels for scoring only. Reusing these labels across branches does not create independent tasks. Log rollout seconds and tokens, teacher-scoring seconds and input positions, update seconds and input/loss positions, and total training seconds including switching. Record evaluation prompt/output tokens and seconds. No persistent teacher-prefix cache in this implementation. Teacher distributions are materialized and detached before student updates, with one common base model resident. Verify nonzero finite adapter gradients, base hashes and exact reset probe logits. Equal steps do not imply equal cost. No useful-cost advantage unless performance is comparable; no repayment claim from faster wrong answers. Human effort, energy and monetary costs unmeasured. Training recall, immediate transfer, later retention and correction are distinct; only the first two are tested.
